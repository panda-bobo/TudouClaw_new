## Locked-in decisions (do NOT re-debate)

1. **Single theme target** — the `tech` theme replaces both legacy themes
   in Phase 4. No 3rd theme alongside.
2. **English default** — new tech-mode pages don't use `data-i18n` attrs;
   text is hard-coded English. Legacy pages keep their bilingual behavior.
3. **No external CSS frameworks** — Tailwind utilities from stitch HTML get
   translated into our `.tc-*` component classes in `theme-tech.css`. No
   Tailwind CDN.
4. **Stitch is design reference, NOT code source** — port the visual
   structure, but the actual JS/data wiring uses our existing portal API
   handlers.
5. **Commit cadence** — every ~5 ported pages, one commit. Follow existing
   commit-message style (`feat(tech-theme): Phase 2 batch N — ...`).
6. **Portrait gallery** — 14 realistic AI-rendered persona PNGs at
   `app/static/robots/aether/aether_<role>.png`. Sourced from stitch_agent_32.
   Mapping in `_AETHER_PORTRAITS` set + `_AETHER_ALIASES` map (in
   portal_bundle.js around line 2945).

## Where the code is

| File | Role |
|---|---|
| `app/server/static/css/theme-tech.css` | All design tokens + `.tc-*` component library + sidebar/topbar overrides. ~860 lines. Tokens gated under `[data-theme="tech"]`. |
| `app/templates/portal.html` | Loads `theme-tech.css` and runs a tiny boot script that reads `localStorage.tudou_theme` and sets `<html data-theme="tech">` BEFORE body paints (avoids flash). |
| `app/api/main.py` | Mounts `/static/css` → `app/server/static/css/` (must be BEFORE the `/static` catch-all mount or MIME breaks). |
| `app/server/static/js/portal_bundle.js` | All `renderXxxTech()` functions live here. Search for `// ============ Tech (Aether) theme` markers. |
| `app/static/robots/aether/aether_*.png` | 14 realistic persona portraits. Don't move/delete. |

Key helpers (already defined; reuse them):
- `_techPageHeader({label, title, actions})` — stitch-style page header.
- `_techHubPage(opts, tabs, key)` — page with chip tab strip, returns
  `{html, current, bodyId}`. Used by all hubs.
- `_techWrapTopLevel(opts, legacyFn)` — wraps a legacy renderer with a
  tech header + container, swaps `#content` ids around legacyFn.
- `_techWrapLegacy(opts, legacyHtml)` — same but takes pre-rendered HTML.
- `_aetherAvatarUrl(role)` — returns `/static/robots/aether/aether_X.png`,
  with alias map for unknown roles.

Pattern for porting a renderer (use this template):
```js
function renderXxx() {
  try {
    if (localStorage.getItem('tudou_theme') === 'tech') return renderXxxTech();
  } catch (e) {}
  // ... existing legacy code ...
}

function renderXxxTech() {
  var c = document.getElementById('content');
  // Build HTML using _techPageHeader + .tc-card / .tc-panel / .tc-grid / etc.
  c.innerHTML = ...;
}
window.renderXxxTech = renderXxxTech;
```

## Known issues / outstanding decisions

- **Card sizing on Agent Directory** — last user feedback was "too big".
  Current state: hero is 4:3 aspect, grid `minmax(240px, 1fr)`, avatar
  `object-position: center 22%`. If user still says too big, reduce min
  column to 220 or shorten hero to 3:2 aspect.
- **Avatar set is 14 portraits** — covers most roles. Roles
  `meeting / specialist / tech_expert / media / architect / devops /
  product_architect` use aliased portraits. If user wants more variety,
  source additional images (other stitch zips have variants) or keep
  pixel-art for those by adjusting `_aetherAvatarUrl` to return null
  for unmapped roles.
- **Sidebar slim mode label tooltips** — current overrides hide labels
  via `display:none` and rely on the `title` attribute. If a user
  reports a missing tooltip, check the corresponding HTML in
  `portal.html:1390-1426` has a proper `title` attr.
- **Branding live preview** — the input `oninput` handlers update
  preview text but don't update the live `_applyBranding()` until Save
  is clicked. Acceptable for now; could be made fully live later.
- **`renderRagProviders` is referenced by Knowledge hub but not
  defined** — when user picks "RAG Providers" tab they see "Tab not
  yet implemented". Defining it is part of batch 4.
