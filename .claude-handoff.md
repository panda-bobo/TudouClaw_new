# Tech Theme — Handoff (2026-05-04, late session)

This doc tells the next Claude session how to pick up the **tech-theme
migration** without re-discovering the architecture from scratch.

---

## TL;DR

The user migrated the TudouClaw portal from a Linear-dark + Claude-light
two-theme system to **a single new theme called "tech" / "Aether"**,
modeled on 33 stitch-generated mockups. **Almost every user-visible
page now has either a full stitch port or a tech-styled hero header.**

Activate / disable:
```js
localStorage.setItem('tudou_theme', 'tech'); location.reload();
localStorage.removeItem('tudou_theme'); location.reload();
```

### Infrastructure changes

* **`_techHubPage`**: dropped the "CONFIGURATION + Roles & Skills" h2 above
  tab strips. The topbar already shows the hub identity, and each
  sub-page renders its own hero, so the parent h2 was redundant.
  Affects all five hubs (Roles & Skills / Knowledge & Memory / Tools &
  Approvals / Integrations / Settings).
* **All five hubs got tab parity restored**: Settings now has 11 tabs
  matching legacy (Branding / System / Global Config / LLM Providers /
  MCP Servers / LLM Tiers / Node Config / Worker Nodes / Audit Log /
  API Tokens / Permissions). Tools & Approvals expanded to 5 tabs
  (was calling phantom functions). Roles & Skills wires the V2-mode
  sub-tabs (FSM Templates / LLM Tier Binding).
* **Integrations hub**: dropped Meetings tab (redundant with Projects
  > Meetings).
* **Topbar add-buttons**: `renderCurrentView` no longer populates
  `actionsEl.innerHTML` for case 'channels' / 'scheduler' / 'mcpconfig' /
  'workflows' / 'integrations' in tech mode. Each page renders its own
  primary pill in the hero — so the action stays bound to the active
  page (no more "Add Channel" leaking into the Inbox tab).
* **Global modal CSS**: `[data-theme="tech"] .modal-overlay`,
  `#modal-overlay`, plus `body > div[style*="position:fixed"]` with
  `z-index:9999 / 999 / 1000` selectors all get the glass overlay.
  Inner panels with `background:var(--bg)` / `var(--surface*)` /
  `border-radius:10px` / `border-radius:12px` get glass-panel chrome
  (rgba(31,31,39,0.85) + 20px blur + inset highlight + 60px ambient
  indigo shadow + r-xl corners). This auto-skins the ~20+ dynamic
  modals across the codebase without per-modal rewrites.
* **Button parity**: `.btn-primary` and `.tc-btn-primary` now share
  the same recipe — `var(--primary-fixed)` bg, `var(--on-primary-fixed)`
  text, mono uppercase 11px tracking 0.05em, no border, 14px ambient
  indigo glow → 22px on hover, scale-0.97 active.
* **Legacy var bridge** in `theme-tech.css`: maps `--bg/--bg2/--surface2/
  --text/--text2/--text3/--border/--border-light/--warning/--success/
  --info/--overlay-N/--primary-tint-N` to tech equivalents so any
  un-ported page gets tech tokens automatically.
* **`.card`/`.btn`/`.tag`/forms/tables/.modal/code/pre/scrollbar**:
  global tech-mode overrides re-skin every common legacy primitive.
* **Login `</head>` duplicate** removed (was malformed HTML).
* **Aether avatars**: `_getAgentRobotSrc` returns `/static/robots/aether/aether_<role>.png`
  in tech mode (from a 14-portrait gallery + role aliases).
* **Skill Store**: noisy auto-tag filter row collapsed to a clear-pill
  that only shows when an active tag filter is set; redundant
  per-source pills removed from stats line; stats simplified to mono
  "N SKILLS · M INSTALLED".

### What's intentionally NOT touched

* `renderConfig` (Global Config) — large legacy page with role presets
  / scene prompts / tool risk grid / fork policy. Bridge auto-skins
  acceptably; full visual rebuild would be ~3 days.
* `renderProjectDetail` body for the 5 panes — labels/buttons English-
  ified, headers swapped, but each pane (Overview / Goals / Milestones
  / Deliverables / Issues / Team Chat) still uses legacy card layout.
  Bridge handles it.
* `renderCanvasPage` (workflow canvas SVG editor) — header swapped but
  the SVG drag-drop logic kept untouched. Stitch_19 has a complex
  inspector + node toolbox layout that would need 2+ days.
* `_kmShowCreateDomainKb` (KB Create modal) — modal opens with stitch
  glass chrome via the global override, but the form sections (Embed
  source radio, embedding model dropdown, reranker dropdown, etc.)
  use legacy `.form-group` styling that auto-skins via the global rules.

## How to start the next session

1. Read this file.
2. `git log --oneline -30` — confirm baseline (~50 tech-theme commits
   on top of the original Phase 2 batches).
3. Browse the live portal at `http://localhost:9090` with
   `localStorage.setItem('tudou_theme', 'tech')` and verify pages.
4. If the user reports a specific page looking off:
   - Find its renderer (grep for the route name in `showView`).
   - If it has a `_techXxx` branch, refine that.
   - If it doesn't have one yet, look up the matching stitch design
     in `/tmp/stitch_review/stitch_agent_<N>/code.html` and add a
     tech check that swaps the layout.
5. Modals: most go through `.modal-overlay`/`.modal` (legacy template-
   defined) or `showModalHTML(html)` (z-index:1000 dynamic). Both are
   captured by the global CSS rules — if a modal looks unstyled,
   check that its outer div uses `position:fixed` + a recognized
   z-index OR add a more specific selector.

## Known issues / decisions

* **Persistent session checkbox** in login: CSS slot `.tech-persistent-session`
  exists but no JS injection — if the user wants this visible, inject
  via DOM after the password form. Backend session TTL is fixed at
  86400s so it's currently a UX-only toggle.
* **LOST CREDENTIAL?** link in login: clickable but no handler. Users
  reset by checking server logs. Could open a help modal if pressed.
* **Workflow Editor canvas** (renderCanvasPage / inner SVG editor):
  hero done, body deferred. stitch_19 has a complex node-toolbox +
  property-inspector layout that would replace the entire SVG canvas
  rendering — high risk, low new functionality. Phase 4 candidate.
* **Avatar set is 14 portraits** — `_AETHER_ALIASES` maps unmapped
  roles to similar archetypes. If the user wants more variety, source
  additional images.

## Phase 4 (after all pages ported)

- Delete the legacy theme infrastructure (Linear-dark + Claude-light
  tokens in `portal.html`, the theme-toggle button, `data-theme="light"`
  rules).
- Make `data-theme="tech"` the unconditional default by setting it in
  the template root `<html>` directly + removing the localStorage gate.
- Strip `_renderXxxLegacy` private functions and the `if (_techXxx)`
  branches — each `renderXxx` becomes the tech version.
- Drop the legacy var bridge (it's load-bearing during the migration
  but creates aliasing confusion long-term).
